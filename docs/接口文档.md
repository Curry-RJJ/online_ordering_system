# 在线订餐系统接口文档

## 1. 文档说明

- 项目名称：`online_ordering_system`
- 后端框架：`Flask`
- 认证方式：`Flask-Login Session/Cookie`
- 默认服务地址：`http://localhost:5000`
- 接口风格：以服务端渲染页面为主，部分场景提供 `JSON` 接口

## 2. 通用约定

### 2.1 角色说明

- `user`：普通用户
- `merchant`：商家管理员
- `admin`：系统管理员

### 2.2 返回类型说明

- `HTML`：返回页面模板
- `Redirect`：处理完成后跳转到目标页面，并通过 `flash` 返回提示信息
- `JSON`：返回结构化数据，主要用于异步请求

### 2.3 常见状态码

- `200`：请求成功
- `302`：表单提交成功后重定向
- `401`：未登录，通常会跳转到登录页
- `403`：权限不足，通常会重定向并提示
- `404`：资源不存在
- `500`：服务器内部错误

### 2.4 通用 JSON 返回示例

成功：

```json
{
  "success": true,
  "message": "操作成功"
}
```

失败：

```json
{
  "success": false,
  "message": "权限不足"
}
```

## 3. 认证与用户模块

路由前缀：`/auth`

### 3.1 用户注册

| 项目 | 内容 |
| --- | --- |
| URL | `/auth/register` |
| 方法 | `GET`, `POST` |
| 权限 | 无 |
| 返回 | `HTML` / `Redirect` |

`POST` 表单参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `username` | `string` | 是 | 用户名 |
| `password` | `string` | 是 | 密码 |

处理逻辑：

- 用户名唯一
- 密码使用 `Werkzeug` 哈希存储
- 注册成功后跳转到登录页

### 3.2 用户登录

| 项目 | 内容 |
| --- | --- |
| URL | `/auth/login` |
| 方法 | `GET`, `POST` |
| 权限 | 无 |
| 返回 | `HTML` / `Redirect` |

`POST` 表单参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `username` | `string` | 是 | 用户名 |
| `password` | `string` | 是 | 密码 |

说明：

- 登录成功后优先跳转 `next` 指定页面
- 未指定 `next` 时默认跳转到餐厅列表页

### 3.3 用户退出登录

| 项目 | 内容 |
| --- | --- |
| URL | `/auth/logout` |
| 方法 | `GET` |
| 权限 | 已登录 |

| 项目 | 内容 |
| --- | --- |
| URL | `/auth/profile` |
| 方法 | `GET`, `POST` |
| 权限 | 已登录 |

`POST` 表单参数：

## 5. 权限申请与审核模块

| 项目 | 内容 |
| --- | --- |
| URL | `/auth/apply_admin` |
| 方法 | `GET`, `POST` |

- `application_type=admin` 时授予管理员角色

| 项目 | 内容 |
| --- | --- |
| URL | `/auth/admin/applications/<app_id>/reject` |
| 方法 | `GET` |
| 权限 | `admin` |
| 返回 | `Redirect` |

### 5.5 商家管理员申请管理商家

| 项目 | 内容 |
| --- | --- |
| URL | `/auth/merchant/apply_restaurant` |
| 方法 | `GET`, `POST` |
| 权限 | `merchant` |
| 返回 | `HTML` / `Redirect` |

`POST` 表单参数：

通用参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `application_type` | `string` | 是 | `existing` 或 `new` |
| `reason` | `string` | 否 | 申请理由 |

当 `application_type=existing`：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `restaurant_id` | `int` | 是 | 申请管理现有商家 ID |

当 `application_type=new`：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `restaurant_name` | `string` | 是 | 商家名称 |
| `restaurant_description` | `string` | 否 | 商家描述 |
| `restaurant_address` | `string` | 否 | 商家地址 |
| `restaurant_phone` | `string` | 否 | 商家电话 |
| `cuisine_type` | `string` | 否 | 菜系类型 |

说明：

- `existing`：申请管理已有商家
- `new`：先创建一个下线商家，再提交审核申请

### 5.6 审核通过商家管理申请

| 项目 | 内容 |
| --- | --- |
| URL | `/auth/admin/merchant_applications/<app_id>/approve` |
| 方法 | `GET` |
| 权限 | `admin` |
| 返回 | `Redirect` |

说明：

- 将申请用户绑定到目标餐厅
- 若为新建商家申请，通过后餐厅默认仍保持下线状态

### 5.7 拒绝商家管理申请

| 项目 | 内容 |
| --- | --- |
| URL | `/auth/admin/merchant_applications/<app_id>/reject` |
| 方法 | `GET` |
| 权限 | `admin` |
| 返回 | `Redirect` |

说明：

- 若申请类型为 `new`，会删除创建但尚未启用的餐厅记录

## 12. 补充说明

### 12.1 认证说明

- 本项目主要使用浏览器 Cookie 维持登录态
- 使用异步接口时，前端需携带当前登录会话

### 12.2 文件上传说明

- 支持的图片类型由应用配置限制
- 常见上传目录：
  - `app/static/images/dishes`
  - `app/static/images/logos`
  - `app/static/images/banners`

### 12.3 当前接口特点

- 页面接口多，适合服务端模板渲染项目
- 异步接口主要集中在购物车、状态切换、搜索和审核场景
- 部分删除/审核类接口目前仍使用 `GET`，更偏项目演示与后台管理场景
