### 3.2 Bug 详情

#### **BUG-001: MySQL 数据库缺失 `discount_rate` 字段 🔴**

*   **严重程度**: 致命 (P0)
*   **位置**: `app/models.py` - `Dish` 类
*   **问题描述**: 
    在 MySQL 生产环境下运行查询时抛出 `OperationalError: (1054, "Unknown column 'dish.discount_rate' in 'field list'")`。这是由于物理表结构与 SQLAlchemy 模型定义不同步导致的。

*   **源代码 (有 Bug)**:
    ```python
    # 物理数据库表中仅有基础字段，未执行迁移
    # 执行查询时报错
    dishes = Dish.query.filter_by(restaurant_id=id).all()
    ```

*   **修复方案**:
    开发了自动化迁移脚本 `migrate_db.py`，动态检测并补全缺失列。
    ```python
    # migrate_db.py 部分代码
    if 'discount_rate' not in columns:
        db.session.execute(text("ALTER TABLE dish ADD COLUMN discount_rate FLOAT"))
        db.session.commit()
    ```

*   **影响范围**: 导致生产环境所有商家详情页面无法访问（500 错误）。
*   **状态**: ✅ 已修复

---

#### **BUG-004: Docker 容器时区未同步导致订单时间偏差 🔴**

*   **严重程度**: 严重 (P1)
*   **位置**: `Dockerfile` / 基础环境配置
*   **问题描述**: 
    容器默认运行在 UTC 时区，导致所有产生的订单记录在数据库中的 `created_at` 时间比北京时间晚 8 小时。

*   **源代码 (有 Bug)**:
    ```dockerfile
    FROM python:3.7-slim
    COPY . /app
    WORKDIR /app
    CMD ["python", "run.py"]
    ```

*   **修复方案**:
    在 Dockerfile 中显式声明时区并安装 `tzdata` 包。
    ```dockerfile
    FROM python:3.7-slim
    ENV TZ=Asia/Shanghai
    RUN ln -snf /usr/share/zoneinfo/$TZ /etc/localtime && echo $TZ > /etc/timezone
    ```

*   **影响范围**: 订单配送时间计算错误，影响财务对账和配送逻辑。
*   **状态**: ✅ 已修复

---

#### **BUG-005: Docker 挂载目录权限冲突导致图片上传失败 🔴**

*   **严重程度**: 严重 (P1)
*   **位置**: `app/utils.py` - `save_uploaded_image`
*   **问题描述**: 
    在 Docker 环境下，由于宿主机挂载的 `static/uploads` 目录权限属于 root 用户，而容器内 Flask 进程以非 root 用户运行，导致图片保存时报 `Permission Denied`。

*   **源代码 (有 Bug)**:
    ```python
    def save_uploaded_image(file):
        # 此时目录可能不可写
        file.save(os.path.join(upload_dir, filename))
    ```

*   **修复方案**:
    在部署脚本 `entrypoint.sh` 中增加权限自愈逻辑。
    ```bash
    # entrypoint.sh
    mkdir -p /app/app/static/images/uploads
    chmod -R 777 /app/app/static/images/
    exec "$@"
    ```

*   **影响范围**: 商家无法添加新菜品图片，功能核心受损。
*   **状态**: ✅ 已修复

---

#### **BUG-012: 高并发下手机号唯一性校验竞争 🔴**

*   **严重程度**: 严重 (P1)
*   **位置**: `app/routes/auth.py` - `register` 函数
*   **问题描述**: 
    在高并发场景下，两个用户同时使用相同手机号注册。由于代码先查询再插入，存在竞态条件，导致数据库抛出唯一约束冲突异常。

*   **源代码 (有 Bug)**:
    ```python
    user = User.query.filter_by(phone=phone).first()
    if not user:
        new_user = User(phone=phone, ...)
        db.session.add(new_user)
        db.session.commit()
    ```

*   **修复方案**:
    使用数据库原子的唯一约束并配合异常捕获。
    ```python
    try:
        new_user = User(phone=phone, ...)
        db.session.add(new_user)
        db.session.commit()
    except IntegrityError:
        db.session.rollback()
        return "手机号已被占用", 400
    ```

*   **影响范围**: 注册接口稳定性不足，偶发 500 系统错误。
*   **状态**: ✅ 已修复
